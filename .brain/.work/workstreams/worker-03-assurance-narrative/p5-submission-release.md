# Worker 03 — Assurance, Creator UX, Narrative, and Submission

## P5 — Submission Release

**Status:** `PLANNED`  
**Primary owner:** Worker 03  
**Track:** 04 — Visual Art & Design Assist  
**Hackathon role:** Live sprint

## Objective

Package and submit the final repository, README, video, screenshots, reports, and disclosures.

## Entry gate

All critical release checks pass and demo is frozen.

## Scope and tasks

Set repository visibility; validate README; add `.env.example`; run secret/path scan; confirm license; verify live-demo URL; save submission confirmation; archive release hash.

## Receiving-party review

All workers sign the release candidate; Worker 3 submits only after the checklist is green.

## Acceptance evidence

Clean clone works, artifacts are present, claims match capability ledger, reused work is disclosed, and required event fields are complete.

## Risks and non-goals

Stale link; private repo; missing video; undocumented dependency; last-minute feature merge.

## Handoff / dependency

P6 post-event work is separate from submission claims.

## Required phase-close record

- Changed paths and commit hash.
- Command or test used for acceptance.
- Evidence file, report, screenshot, or recording.
- Known limitations and unsupported cases.
- Updated claims/capability status.
- Receiving reviewer decision: `PASS`, `CONDITIONAL PASS`, or `HOLD`.

## Definition of done

This phase is not complete because the file exists. It is complete only when the acceptance evidence is produced, the receiving reviewer runs the acceptance command, and the capability ledger is updated honestly.
